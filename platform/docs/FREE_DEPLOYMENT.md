# No-card deployment for a 2–3 month handover

This deployment keeps the application reachable through one Netlify URL without requiring a payment card:

```text
Browser → Netlify Next.js → Render FastAPI → Neon PostgreSQL
                              ↑
                    GitHub weekly schedule
```

The hosted version intentionally does not run Redis, Celery worker, or Celery Beat. Manual Scopus updates already execute directly in FastAPI. The optional GitHub workflow calls the same synchronization service weekly through a secret-protected endpoint.

## Before deployment

1. Put the repository in GitHub. Keep it private if required by the institution.
2. Confirm that `platform/.env` is not tracked by Git. Never paste its contents into GitHub.
3. Create new production values for the administrator password, `SCHEDULED_SYNC_SECRET`, and Elsevier API key. Do not reuse local development secrets.
4. Create a long random scheduling secret in PowerShell if needed:

   ```powershell
   [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
   ```

## 1. Create the Neon database

1. Sign in at <https://neon.com> and create a project in an EU region where available.
2. Copy the **pooled** PostgreSQL connection string from the Neon dashboard. It begins with `postgresql://` and should include `sslmode=require`.
3. Keep the connection string private. It will be entered only in Render as `DATABASE_URL`.

The backend automatically converts provider-style `postgresql://` URLs to the installed psycopg v3 driver format. On first start it applies Alembic migrations automatically.

## 2. Deploy the FastAPI backend on Render

1. Sign in at <https://render.com> and choose **New → Blueprint**.
2. Connect the GitHub repository. Render detects the root `render.yaml` file.
3. Choose the Free instance and enter these prompted secret values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon pooled connection string |
   | `ELSEVIER_API_KEY` | Production Scopus API key |
   | `CORS_ORIGINS` | Temporary Netlify URL initially; update after Netlify is created |
   | `INITIAL_ADMIN_NAME` | Name of the first administrator |
   | `INITIAL_ADMIN_EMAIL` | Institutional email of the first administrator |
   | `INITIAL_ADMIN_PASSWORD` | Unique temporary password, at least 12 characters |
   | `SCHEDULED_SYNC_SECRET` | Long random value created above |

4. Deploy the Blueprint. `SECRET_KEY` is generated by Render and must remain unchanged while sessions are in use.
5. Wait for `/api/v1/health` on the generated `https://...onrender.com` domain to return `{"status":"ok",...}`.
6. Copy the Render backend URL without a trailing slash.

The startup command runs migrations and creates the first administrator only when the database contains no users. It never adds the mock professors. After the first successful login, the initial password can be removed from Render's environment; existing accounts remain in Neon.

## 3. Deploy the Next.js frontend on Netlify

1. Sign in at <https://netlify.com> and choose **Add new project → Import an existing project**.
2. Select the same GitHub repository. The root `netlify.toml` supplies the base directory and build command.
3. Add this environment variable before the first production build:

   ```text
   BACKEND_INTERNAL_URL=https://your-render-service.onrender.com
   ```

4. Deploy and open the generated `https://...netlify.app` link.
5. Return to Render and set `CORS_ORIGINS` to the exact Netlify origin, for example `https://example.netlify.app`, then redeploy the backend.

The browser calls `/api/v1/...` on the Netlify origin. Next.js securely proxies those requests to Render, so the existing HttpOnly login cookie remains same-origin from the browser's perspective.

## 5. Enable weekly Scopus updates

In GitHub, open **Settings → Secrets and variables → Actions** and add:

| GitHub secret | Value |
|---|---|
| `RENDER_BACKEND_URL` | Render backend URL without a trailing slash |
| `SCHEDULED_SYNC_SECRET` | Exactly the same value configured in Render |

Open **Actions → Weekly Scopus synchronization → Run workflow** once to test it. The workflow is also scheduled for Sunday at 03:17 UTC. It wakes the Render backend and updates all active professors with confirmed Scopus IDs.

Manual **Update from Scopus** remains available to administrators and does not require Redis or Celery.

## Operating limits for 20 professors

- Render sleeps after 15 idle minutes. The first page request can take about one minute while it wakes.
- Neon Free has finite monthly compute and 0.5 GB storage. Check storage weekly and act at 350 MB rather than waiting for the limit.
- Netlify uses monthly credits for production deploys, compute, bandwidth, and requests. Avoid unnecessary production deployments.
- Render local files are temporary. Excel exports are streamed to the user and should be saved on an institutional computer.
- The schedule is best-effort. Check GitHub Actions after each weekly run and use the manual button if a run fails.

## Backups and handover

Export a database backup at least weekly from a trusted machine with PostgreSQL client tools installed:

```powershell
$env:DATABASE_URL = Read-Host "Neon connection string"
pg_dump $env:DATABASE_URL --format=custom --file="utn-scopus-$(Get-Date -Format yyyy-MM-dd).dump"
Remove-Item Env:DATABASE_URL
```

Store backups only in an approved institutional location. Before handover, transfer ownership of the GitHub, Netlify, Render, and Neon projects to institution-controlled accounts and rotate every secret.

## Rollback

The local Docker Compose environment remains unchanged and still supports PostgreSQL, Redis, Celery worker, and Beat. If the free deployment is unavailable, run the local stack and restore the latest PostgreSQL backup while institutional hosting is arranged.
